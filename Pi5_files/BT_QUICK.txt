================================================================================
  BLUETOOTH TEST BETWEEN TWO RASPBERRY PIS — CHEAT SHEET (WORKING RECIPE)
================================================================================

Verified on two Raspberry Pi 5 boards (Bookworm). Working script — bt_simple_test.py.
The other bt_test*.py scripts are drafts, do not use them (see section 8).


1️⃣  SYSTEM SETUP (once on EACH Pi)
──────────────────────────────────────────────────────────────────────────────

a) Enable and start Bluetooth:
   $ sudo systemctl enable bluetooth
   $ sudo systemctl start bluetooth
   $ sudo hciconfig hci0 up
   $ sudo hciconfig hci0 piscan

b) Enable bluetoothd compat mode (REQUIRED for sdptool/RFCOMM):
   $ sudo mkdir -p /etc/systemd/system/bluetooth.service.d
   $ sudo tee /etc/systemd/system/bluetooth.service.d/override.conf << 'EOF'
   [Service]
   ExecStart=
   ExecStart=/usr/libexec/bluetooth/bluetoothd --compat
   EOF
   $ sudo systemctl daemon-reload
   $ sudo systemctl restart bluetooth
   $ sudo hciconfig hci0 up
   $ sudo hciconfig hci0 piscan

c) Register the Serial Port service (SPP) on channel 1:
   $ sudo sdptool add --channel=1 SP

   Check:
   $ sudo sdptool browse local
   # Should show "Serial Port" / Channel: 1

Without step (b), the RFCOMM connection fails with "Connection refused" even
if Bluetooth is enabled and the devices can see each other.


2️⃣  PAIRING (ONCE, after system setup)
──────────────────────────────────────────────────────────────────────────────

⚠️ IMPORTANT: pairing must be initiated from ONLY ONE SIDE.
If both Pis try to "pair" with each other at the same time, you get a race
condition and "Failed to pair: org.bluez.Error.AuthenticationFailed".

On the LISTENER Pi (e.g. bropi/robotA) — just wait, do NOT press pair:
   $ bluetoothctl
   [bluetoothctl]> agent on
   [bluetoothctl]> default-agent
   (leave it open and wait)

On the INITIATOR Pi (e.g. bropi2/robotB) — scan and pair:
   $ bluetoothctl
   [bluetoothctl]> agent on
   [bluetoothctl]> default-agent
   [bluetoothctl]> scan on
   (wait 10-15s until [NEW] Device <other Pi's address> appears)
   [bluetoothctl]> scan off
   [bluetoothctl]> pair <LISTENER_BD_ADDR>

Both sides will show a prompt:
   [agent] Confirm passkey NNNNNN (yes/no):
Enter yes on BOTH Pis (the passkey must match on both!).

After "Pairing successful" on both Pis run:
   [bluetoothctl]> trust <OTHER_PI_BD_ADDR>
   [bluetoothctl]> quit

If the device shows "not available" when pairing — do scan on/off first to
refresh the cache (BlueZ forgets devices that drop out of range).


3️⃣  RUNNING THE TEST
──────────────────────────────────────────────────────────────────────────────

Find your own BD address (needed by the client):
   $ sudo hciconfig | grep "BD Address"

On the SERVER Pi (e.g. robotA):
   $ cd ~/Documents/RC/Pi5_files
   $ sudo python3 bt_simple_test.py --server robotB

On the CLIENT Pi (e.g. robotB):
   $ cd ~/Documents/RC/Pi5_files
   $ sudo python3 bt_simple_test.py --client robotA

(the address is taken from device/device_id.local.json → peers.<id>.bd_addr,
 or given explicitly: --force-addr AA:BB:CC:DD:EE:FF)

Both scripts must be run WITH SUDO (Bluetooth socket access requires it).


4️⃣  STORING ADDRESSES IN THE CONFIG
──────────────────────────────────────────────────────────────────────────────

device/device_id.local.json on each Pi, e.g. on robotA (bropi):
{
  "id": "robotA",
  "type": "robot",
  "target_host": null,
  "peers": {
    "robotB": {
      "bd_addr": "2C:CF:67:5C:F0:F6"
    }
  }
}

Save it with the helper utility:
   $ python3 bt_setup.py --save-peer robotB 2C:CF:67:5C:F0:F6


5️⃣  TROUBLESHOOTING (step by step)
──────────────────────────────────────────────────────────────────────────────

❌ bt_setup.py --scan finds nothing
  → sudo systemctl status bluetooth (should be active/running)
  → sudo hciconfig (hci0 should be UP RUNNING; if DOWN: hciconfig hci0 up)

❌ "Device not available" when pairing
  → The device fell out of BlueZ's cache. Run scan on, wait,
    see [NEW] Device, then scan off and retry pair.

❌ "Failed to pair: AuthenticationFailed"
  → Pairing was initiated from BOTH sides at once. Retry,
    but only press pair on ONE Pi (see section 2).

❌ "bad bluetooth address" (OSError on bind)
  → In Python: sock.bind(("", channel)) doesn't work on RPi.
    Use sock.bind((socket.BDADDR_ANY, channel)) instead.

❌ "[Errno 13] Permission denied" on connect/bind
  → Run the script with sudo.

❌ "[Errno 22] Invalid argument" on setsockopt BT_SECURITY
  → The bt_security struct is 2 bytes (level + key_size), not 1:
    struct.pack("BB", level, 0), not struct.pack("B", level).

❌ "[Errno 110] Connection timed out" on the client
  → Check the basic link: sudo l2ping -c 3 <BD_ADDR>.
    If l2ping also fails — the Bluetooth link isn't established
    physically (too far, interference, not enabled on the other side).
  → If l2ping works but RFCOMM still times out — most likely the
    bluetoothd compat mode and/or SDP record are missing (sections 1b, 1c).

❌ "[Errno 111] Connection refused" immediately
  → The server isn't listening, or there's no SDP service registered
    on that channel (sudo sdptool add --channel=1 SP on the SERVER),
    or the devices aren't "Paired: yes" yet (bluetoothctl info <addr>).

❌ "[Errno 112] Host is down"
  → The underlying Bluetooth link was lost (often after restarting
    bluetooth). Reset the interface:
    sudo hciconfig hci0 down && sudo hciconfig hci0 up
    sudo hciconfig hci0 piscan
    Check sudo l2ping -c 3 <BD_ADDR> again.

❌ sdptool browse local: "Failed to connect to SDP server... No such
   file or directory"
  → bluetoothd compat mode wasn't applied on this Pi. Check that
    /etc/systemd/system/bluetooth.service.d/override.conf exists
    and contains the correct 3 lines, then daemon-reload + restart.


6️⃣  FULL PROCEDURE FROM SCRATCH (if something broke)
──────────────────────────────────────────────────────────────────────────────

On BOTH Pis:
  1. sudo systemctl restart bluetooth
  2. sudo hciconfig hci0 up && sudo hciconfig hci0 piscan
  3. sudo sdptool add --channel=1 SP
  4. sudo l2ping -c 3 <other Pi's address>   # should be 0% loss

Then pairing (section 2, initiator — ONE side only), then the test
(section 3).


7️⃣  CHECKING CURRENT STATUS
──────────────────────────────────────────────────────────────────────────────

  $ sudo hciconfig                      # adapter status (UP RUNNING?)
  $ bluetoothctl info <BD_ADDR>         # Paired/Bonded/Connected: yes/no
  $ bluetoothctl paired-devices         # list of paired devices
  $ sudo sdptool browse local           # which services are registered
  $ python3 bt_setup.py --config        # current Pi's device_id.local.json

9️⃣  WHAT bt_simple_test.py TESTS
──────────────────────────────────────────────────────────────────────────────

Simple exchange: the client sends "Test 0".."Test 4" as text,
the server replies "OK" to each message. 5 iterations with a 0.1-0.2s pause.

This is the MINIMAL working connection test — it does not include PING/PONG,
exchanging (x, y, yaw), or the speed test from the drafts. If you need to
exchange real position data, the protocol from bt_test_rfcomm.py /
bt_test_auto.py (struct pack 'Ifff' etc.) can be ported into
bt_simple_test.py, which is now on a working foundation.
