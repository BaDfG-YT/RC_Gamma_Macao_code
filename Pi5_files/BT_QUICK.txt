1️⃣  ПЕРВЫЙ РАЗ: НАСТРОЙКА
──────────────────────────────────────────────────────────────────────────────

На СЕРВЕРЕ (например robotA):
  $ python3 bt_setup.py --scan              # Найти другой Pi
  $ python3 bt_setup.py --pair AA:BB:CC:DD:EE:FF  # Сопрячь robotB
  $ python3 bt_setup.py --save-peer robotB AA:BB:CC:DD:EE:FF

На КЛИЕНТЕ (например robotB):
  $ python3 bt_setup.py --scan              # Найти другой Pi
  $ python3 bt_setup.py --pair 11:22:33:44:55:66  # Сопрячь robotA
  $ python3 bt_setup.py --save-peer robotA 11:22:33:44:55:66


2️⃣  БЫСТРЫЙ СТАРТ (если адреса сохранены в device_id.local.json)
──────────────────────────────────────────────────────────────────────────────

Интерактивное меню:
  $ bash bt_quick_start.sh

ИЛИ вручную:

На СЕРВЕРЕ:
  $ python3 bt_test_auto.py --server robotB

На КЛИЕНТЕ (в другом терминале на другом Pi):
  $ python3 bt_test_auto.py --client robotA


3️⃣  ПОДРОБНЫЙ ТЕСТ (если адреса известны явно)
──────────────────────────────────────────────────────────────────────────────

На СЕРВЕРЕ:
  $ python3 bt_test.py --server --target-device robotB --bd-addr AA:BB:CC:DD:EE:FF

На КЛИЕНТЕ:
  $ python3 bt_test.py --client --target-device robotA --bd-addr 11:22:33:44:55:66


4️⃣  ПРОВЕРКА ТЕКУЩЕГО КОНФИГА
──────────────────────────────────────────────────────────────────────────────

  $ python3 bt_setup.py --config        # Показать device_id.local.json
  $ python3 bt_setup.py --list          # Сопряжённые устройства
  $ bluetoothctl show                   # Статус Bluetooth (Linux)


5️⃣  ТИПИЧНЫЙ WORKFLOW
──────────────────────────────────────────────────────────────────────────────

Первый день:
  1. На каждом Pi: python3 bt_setup.py --scan
  2. Запомните адреса (AA:BB:CC:DD:EE:FF формат)
  3. На каждом Pi: python3 bt_setup.py --pair <адрес_другого>
  4. На каждом Pi: python3 bt_setup.py --save-peer <имя_другого> <адрес>

Дальше каждый раз:
  1. На сервере: python3 bt_test_auto.py --server robotB
  2. На клиенте: python3 bt_test_auto.py --client robotA


6️⃣  ПЕРЕМЕННЫЕ СРЕДЫ / ПАРАМЕТРЫ
──────────────────────────────────────────────────────────────────────────────

--channel N           — RFCOMM канал (по умолчанию 1)
--force-addr ADDR     — явный адрес вместо загрузки из конфига
--timeout N           — таймаут соединения (секунды)


7️⃣  ЕСЛИ ЧТО-ТО НЕ РАБОТАЕТ
──────────────────────────────────────────────────────────────────────────────

❌ "Connection refused"
  → Убедитесь, что сервер запущен первым
  → Проверьте адреса (bluetoothctl paired-devices)
  → Может понадобиться повторное сопряжение

❌ "No module named 'socket'"
  → python3 bt_setup.py --list (проверьте что работает)
  → Возможно нужны зависимости: sudo apt-get install python3-bluez bluez-tools

❌ Низкая скорость
  → Это нормально для RFCOMM (~100-200 пак/сек)
  → Для более высокой скорости рассмотрите SPP или BLE

❌ "No such file or directory" для device_id.local.json
  → Убедитесь что файл есть: ls -la ../device/
  → Если нет: скопируйте device_id.defaults.json и отредактируйте

9️⃣  ЧТО ТЕСТИРУЕТСЯ
──────────────────────────────────────────────────────────────────────────────

✓ Соединение RFCOMM между двумя Pi
✓ PING/PONG (проверка отклика)
✓ Быстрый обмен данными позиции (x, y, yaw)
✓ Пропускная способность (100 пакетов подряд)

Примеры данных:
  PING: 5 байт (заголовок + номер)
  DATA: 13 байт (заголовок + seq + x,y,yaw как 3 float)
  Ожидается: ~100-200 пакетов в секунду
